# 海外 SRC：业务逻辑（支付 / 优惠 / 竞态 / 工作流）

扫描器几乎找不到这类洞。已授权、**自建测试账号**、**不要对生产造成资金损失**。

配套：`src-idor`（对象级）+ 本技能（规则级）→ **`src-triage`（校验松但钱/权/数据都不变 = 不是洞）** → `src-retest` → `src-report-writing`。

---

## 0. 合规

- [ ] policy 允许测支付/优惠券；很多要求 **用官方沙盒卡 / 0 元商品**
- [ ] 禁止刷真实优惠到可用余额后提现
- [ ] 竞态只打 **测试商品**，成功一次即停
- [ ] 审批流不要把真实员工卷进去

---

## 1. 先画「钱和状态」怎么走

用 browser MCP + 代理流量，记下每一步：加购 → 改数量 → 用券 → 下单 → 支付回调 → 发货 / 退款 / 取消。

关注字段：`price` `qty` `amount` `discount` `coupon` `currency` `credits` `points` `status` `step` `role`。

---

## 2. 最小实验（每次只改一个假设）

| 假设 | 做法 | 成功证据 |
|---|---|---|
| 客户端价格 | 把 `price=0.01` 或负数量重放 | 订单总额跟着改且支付成功 |
| 数量 | `qty=-1` / `0` / `999999` | 退款到账或库存异常 |
| 优惠券 | 已用券重放、他人券、叠券、改 `percent=100` | 实付不符规则 |
| 币种 | `USD`→`IDR` 等低价值 | 实付按错汇率 |
| 跳步 | 直接 POST 支付成功 / 发货 | 未付款变成已完成 |
| 竞态 | 余额 10、并发两笔 10（2～5 并发，不要 1000） | 两笔都成功 |
| 邀请/返利 | 自己邀自己、改 referrer id | 额外发奖 |
| 试用 | 改到期时间、删订阅仍用功能 | 仍能访问付费功能 |

IDOR 式「看别人订单」归 `src-idor`，这里报「规则被绕过」。

---

## 3. 定级

按**实际少付/多拿**的钱或权限：能白拿资金/库存 → High～Critical；仅本地显示错价格未下单 → 不报。

**不是洞（`src-triage` drop）**：评分越界、显示名特殊字符、验证码回显但接口无敏感操作、刷点赞/浏览无经济影响。必须在 **attack 的 `response.body`** 里看到订单金额/钱包/角色与 control 不同。
